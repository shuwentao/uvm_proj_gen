uvm_proj_gen —— UVM 工程生成器

一条命令生成新的 UVM 验证工程，并从 GitHub 仓库清单（repo.list）里 按需勾选要挂载的 submodule（uvm_base / dvp_vip / 将来的 AXI、SPI…）， 从而组合出各种不同的仿真环境。

1. 目录结构

uvm_proj_gen/
├── create_project.sh        主脚本
├── repo.list                ★ GitHub 仓库清单（手动增删、控制默认勾选）
├── templates/               模板（@P@ 会替换成工程名）
│   ├── gitignore.tpl
│   ├── Makefile.tpl
│   ├── README.html.tpl      工程根目录的 README
│   ├── src_README.txt        ← 已移除
│   ├── out_if.sv.tpl        输出侧接口
│   ├── pkg_dvp.sv.tpl       挂了 dvp_vip 时用的 pkg
│   ├── top_dvp.sv.tpl       挂了 dvp_vip 时用的 top
│   ├── pkg_base.sv.tpl      未挂协议 VIP 时的 pkg 骨架
│   ├── top_base.sv.tpl
│   └── repo_fragments/      ★ 每个仓库的"接入片段"
│       ├── uvm_base.frag    filelist 片段
│       ├── dvp_vip.frag
│       ├── dvp_vip.mk       Makefile 变量
│       └── dvp_vip.flags    DEFS / PLUS
├── README.html
└── .gitignore

2. 用法

# 查看可用仓库
./create_project.sh --list

# 交互式（列出清单，手选序号；回车=默认带 * 的）
./create_project.sh my_proj

# 非交互：直接用 repo.list 里的默认勾选
./create_project.sh my_proj -y

# 指定要挂的仓库
./create_project.sh my_proj -r uvm_base,dvp_vip
./create_project.sh my_proj -r uvm_base,dvp_vip --dir ~/work

# 本地开发：不 git submodule add，改为软链到 ../../<仓库名>
./create_project.sh my_proj -r uvm_base,dvp_vip --local

# 用别的清单文件
./create_project.sh my_proj --config ./my_repo.list

选项

选项说明
-r, --repos <a,b,c>指定要挂载的仓库名（逗号分隔）
-y, --yes非交互，采用 repo.list 的默认勾选
--dir <path>工程创建位置（默认当前目录）
--local用软链接代替 git submodule add（本地联调用）
--list只打印仓库清单并退出
--config <file>使用其它仓库清单（默认 ./repo.list）

3. repo.list：手动控制 submodule

# 格式: 名称 | 本地路径 | GitHub URL | 说明 | 默认启用(1/0)
uvm_base | lib/uvm_base | git@github.com:shuwentao/uvm_base.git | 通用 UVM 母版库（必选底座）    | 1
dvp_vip  | lib/dvp_vip  | git@github.com:shuwentao/dvp_vip.git  | DVP 测试 IP（BFM + UVM agent） | 0

# axi_vip | lib/axi_vip | git@github.com:shuwentao/axi_vip.git  | AXI VIP（待实现）             | 0
# spi_vip | lib/spi_vip | git@github.com:shuwentao/spi_vip.git  | SPI VIP（待实现）             | 0
  • 临时禁用：在行首加 #
  • 改默认勾选：改最后一列 1 / 0
  • 换地址：改第 3 列（公开仓库建议用 HTTPS URL，便于协作者克隆）

新增一个 VIP（两步）

  1. 在 repo.list 加一行
  2. 建 templates/repo_fragments/<名称>.frag（该仓库要加进 filelist 的 incdir + 源文件）； 需要 Makefile 变量就再加 <名称>.mk，需要编译宏/plusarg 就加 <名称>.flags
# templates/repo_fragments/axi_vip.frag
+incdir+./lib/axi_vip/src
./lib/axi_vip/src/axi_vip_pkg.sv
若新 VIP 需要专属的 pkg / top 模板，再加 templates/pkg_axi.sv.tpl 等， 并在 create_project.sh 里按 has_repo axi_vip 选择（与 dvp_vip 的写法一致）。

4. 生成的工程结构

my_proj/
├── lib/
│   ├── uvm_base/    ← submodule（或软链）
│   └── dvp_vip/     ← submodule（或软链）
├── src/             放你的被测设计（空目录，含 .gitkeep）
├── tb/              你的验证代码
│   ├── my_proj_out_if.sv   输出侧接口
│   ├── my_proj_pkg.sv      cfg / 输出观测 / env / test
│   └── my_proj_top.sv      BFM 接口 + DUT + config_db + run_test
├── sim/             ★ 编译相关（make 在本目录运行）
│   ├── filelist.f          按所选仓库自动拼装（路径以 sim/ 为基准）
│   ├── Makefile            真正的 Makefile
│   └── mk_config.mk        按所选仓库生成的 Makefile 变量
├── script/          ★ 空目录：只放你自己写的工具脚本（生成器不往里放东西）
│   └── .gitkeep
├── README.html     工程说明（结构 / 怎么跑 / 下一步要改什么）
└── .gitignore

怎么跑

cd my_proj/sim && make check      # Makefile 只在 sim/ 下
编译产物 simv / csrc / logs / waves 都在 sim/ 下，工程根目录保持干净。

script/ 归你：生成器只建一个空的 script/（带 .gitkeep 便于 git 跟踪）， 里面的脚本全部由你自己写，例如 regress.sh、cov.sh、wave.sh、 gen_case.py 等。生成器不会覆盖这个目录。

生成后要做的事

  1. 把 src/ 里换成你的设计，并在 filelist.f 登记
  2. tb/my_proj_top.sv 里的 u_dut 换成你的模块（默认占位 DUT 是 dvp_rx）
  3. 在 tb/my_proj_pkg.sv 里写你自己的 checker（默认只统计、不做比对）
  4. make check

6. 注意

路径约束：dvp_vip 内部用相对路径 ../uvm_base 引用底座， 所以两个仓库必须放在同一层（生成器统一放在 lib/ 下，已满足）。

必须显式声明构造函数：继承 uvm_base_* 的组件（env / test / agent …）都要自己写 function new(string name="x", uvm_component parent=null); super.new(name,parent); endfunction， 否则 factory 调 new(name,parent) 会报 Error-[TMAFTC] Too many arguments（模板里已写好）。
